# Android 后台道路道具结算设计

## 1. 目标

Android 用户开启“后台挂机”并将应用切到后台或锁屏后，继续按普通道路步行时的规则获得道路道具。回到前台后，背包库存、道具累计统计和掉落日志应体现后台期间的收益，且同一时间片不会重复发放。

本次覆盖 `ITEM_RATES` 中的全部道路掉落：

- 精灵球；
- 高级球；
- 大师球；
- 糖果及现有糖果数量倍率；
- 甜甜蜜；
- 神秘蛋；
- 闪耀护符。

后台道具收益继续受有效随从的 `itemDrop` 增益影响。

## 2. 非目标

- 不在后台播放道路滚动、道具滑入或拾取动画。
- 不依赖 Android 后台继续执行浏览器的每秒 `setInterval`。
- 不模拟钓鱼、自行车路段、大量出没或时空扭曲期间的道路掉落。
- 不在本次改动中补算 GPS、行走距离、孵蛋里程、农场帮手时间或其他前台 Tick 行为。
- 不修改现有自动捕捉、过滤器暂停和精灵球消耗规则。

## 3. 现状与根因

前台道路掉落位于 `src/main.js` 的每秒 Tick 中。普通步行状态下，每个道具都通过存档字段 `_f_<item>` 累加 `ITEM_RATES[item]`；累积值每越过整数 1 次就生成 1 次掉落。随从增益通过 `itemDrop` 机制放大每秒累加值，糖果在掉落时再按 `CANDY_DROP_MULT` 抽取数量倍率。

Android 后台模式目前只调用 `settleBackgroundEncounters(now)`，按时间戳批量结算遇敌、捕获和球消耗。WebView 进入后台后，前台 `onGameTick()` 会被系统节流或暂停，因此 `_f_<item>` 不再推进，用户无法获得糖果等道路道具。

根因是后台时间片结算缺少与前台道路掉落对应的纯数据结算逻辑，而不是道具入库或界面刷新失败。

## 4. 方案选择

采用“扩展后台时间片核心 + 独立纯函数结算道路道具”的方案。

- `src/background-settlement.js` 继续负责时间边界、24 小时上限、时间回拨和时间游标推进，并在相邻遇敌之间暴露时间段回调。
- 新增不依赖 DOM 的后台道路道具模块，负责按有效秒数、`ITEM_RATES`、随从增益和现有小数余数计算掉落。
- `src/battle.js` 的后台结算入口在同一个存档副本中依次完成道路道具和遇敌结算，最后只保存一次。
- 前台动画继续使用 `spawnItemDrop()`；后台直接更新数据，不调用动画、音频或页面 API。

相比直接运行完整前台 Tick，这个方案不依赖 WebView 后台调度，耗电和系统兼容性更可控。相比在 `battle.js` 内临时增加循环，独立纯函数更容易验证幂等性、余数和随从到期边界。

## 5. 数据模型

### 5.1 复用前台掉落余数

继续使用现有 `gameData._f_<item>` 字段作为每类道具的小数累计值，不新增第二套概率进度。

这样可以保证：

- 前台切入后台时继承已经积累但未达到 1 的进度；
- 后台切回前台时，剩余小数继续由前台 Tick 使用；
- 新旧存档无须迁移，缺失字段按 0 处理；
- 后台心跳和前台运行不会各自维护互不相干的余数。

每个余数必须归一化为有限且不小于 0 的数字；非法旧值按 0 处理。

### 5.2 后台统计

在 `background.stats` 中增加：

- `items`：后台累计获得的道具数量映射；糖果记录实际倍率后的数量；
- `itemDrops`：后台累计触发的掉落实例数，糖果无论倍率多少都计 1 次。

缺失或非法字段按空映射和 0 处理，确保旧存档兼容。现有 `encounters`、`caught`、`fled` 和 `ballsUsed` 保持不变。

在 `background` 中增加：

- `roadItemsEnabled`：进入后台时记录的普通道路掉落快照。

## 6. 结算规则

### 6.1 有效时间

后台道路掉落和后台遇敌共用同一个 `settledAt` 时间游标：

1. 进入后台时，将 `settledAt` 设为当前时间并保存。
2. 每次后台心跳或恢复前台时，计算 `elapsedMs = now - settledAt`。
3. 时间相等时不结算；时间回拨时校正游标且不发放道具。
4. 单次最多结算最近 24 小时，超出部分直接跳过并把游标推进到 `now`，与现有后台遇敌规则一致。
5. 只有成功写入存档后结算才生效；保存失败时恢复原存档，下一次可以重试。

道具累加使用 `elapsedMs / 1000` 换算秒数，毫秒部分直接进入 `_f_<item>` 的小数累计值，不单独增加时间余数字段。结算后前台继续使用已有 `_f_<item>` 小数进度。

### 6.2 普通道路快照

进入 Android 后台时记录本次是否允许道路掉落。仅满足以下条件时允许：

- 当前处于普通步行挂机状态；
- 未骑自行车；
- 未钓鱼或等待钓鱼；
- 未处于大量出没或时空扭曲事件区域；
- 未处于切换到自行车路段的过渡状态。

后台期间不模拟道路状态切换。本次后台会话沿用进入后台时的快照：快照不允许掉落时，后台仍可按现有规则结算遇敌，但道路道具收益为 0。

### 6.3 每类道具计算

对 `ITEM_RATES` 中的每个道具执行：

```text
累计值 = 已有 _f_<item>
       + 非增益秒数 × 基础掉落率
       + 增益秒数 × 基础掉落率 × (1 + 随从增益)
掉落实例数 = floor(累计值)
新余数 = 累计值 - 掉落实例数
```

为了正确处理随从在后台期间到期，时间片按 `follower.endsAt` 分成“随从有效”和“随从失效”两段。只有随从的分组映射为 `itemDrop` 且 `boost` 为有效正数时，增益段才使用 `1 + boost` 倍率。

普通道具每次掉落数量为 1。糖果每个掉落实例分别按 `CANDY_DROP_MULT` 抽取倍率，不能先合并实例再只抽一次。

### 6.4 入库与日志

后台入库必须复用与前台一致的数据规则：

- 增加 `gameData.items[item]`；
- 增加 `gameData.stats.totalItemsEarned[item]`；
- 写入 `item_gain` 系统日志，并增加 `background: true` 标记；
- 更新 `background.stats.items` 和 `background.stats.itemDrops`。

为避免长时间后台产生大量日志，同一时间片内相同道具合并为 1 条系统日志，`qty` 记录本次实际获得总量，`drops` 记录掉落实例数。库存和累计统计仍按准确数量增加。

后台模块不调用 `updateBackpack()`、`updateStats()` 或掉落提示。恢复前台后由现有入口统一刷新界面。

## 7. 与遇敌结算的时序

同一后台时间片采用以下顺序：

```text
读取并复制当前存档
  -> 计算受 24 小时上限约束的有效时间范围
  -> 结算开始时间到第 1 次遇敌之间的道路道具
  -> 使用更新后的精灵球与糖果库存结算第 1 次遇敌
  -> 逐段重复“道路道具 -> 遇敌”
  -> 结算最后一次遇敌到时间片结束之间的道路道具
  -> 写入后台统计和时间游标
  -> 严格保存一次
```

`background-settlement.js` 在每次遇敌前调用 `resolveElapsed({ state, from, to })`，并在全部遇敌结束后调用一次尾段回调。道路道具模块在该回调中更新 `_f_<item>`、库存和统计；新获得的球或糖果可参与随后发生的自动捕捉和自动补球。

若捕获过滤器产生“暂停”遭遇，道具只结算到该暂停遭遇的时间点，暂停点之后的道路道具时间留待用户处理遭遇后继续结算，避免遇敌停止后仍跨越暂停点获取收益。

## 8. 幂等性与并发

- 继续使用 `_backgroundSettlementQueue` 串行处理心跳和前台恢复。
- 道具和遇敌共用最终 `settledAt`，相同或更早的 `now` 不会重复结算。
- 所有修改先发生在深拷贝状态中；严格保存成功后才通过 `setGameData()` 生效。
- 若严格保存失败，恢复进入结算前的存档对象和时间游标。
- 有 `pendingEncounter` 时不推进道具或遇敌时间，等待前台恢复该遭遇，避免过滤器暂停期间继续产出。

## 9. 测试策略

### 9.1 纯函数测试

- 固定时间和掉落率，验证精灵球、糖果及其他道具的数量。
- 糖果多个掉落实例分别抽倍率，并累计实际数量。
- 现有 `_f_<item>` 余数跨前台和多个后台心跳连续累加。
- 相同时间戳重复结算不重复发放。
- 时间回拨不发放，24 小时上限与遇敌保持一致。
- 随从 `itemDrop` 增益仅在有效期内生效，跨到期时间正确分段。
- 非普通道路快照不产生道具。
- 非法余数、库存和统计字段安全归一化。

### 9.2 集成测试

- 后台新获得的球可被同一时间片的自动捕捉消耗。
- 自动补球可使用后台新获得的糖果。
- 过滤器暂停时，道具和遇敌都停在同一时间点。
- 严格保存失败后库存、余数和游标全部回滚。
- 恢复前台后只刷新 UI，不重复入库。
- 旧存档缺失新增后台统计字段时可正常加载。

### 9.3 真机验收

1. 记录切入后台前的背包、`totalItemsEarned` 和 `_f_<item>`。
2. 开启后台挂机并锁屏至少 5 分钟。
3. 返回前台，确认糖果和多类道路道具增加，系统日志带后台标记。
4. 使用带 `itemDrop` 增益的随从重复测试，并覆盖随从在锁屏期间到期的情况。
5. 连续快速切换前后台并重复触发心跳，确认库存不重复增加。
6. 在骑行、钓鱼或特殊事件区域进入后台，确认不发放普通道路道具。

## 10. 发布边界

- Android 版本递增 1 个 patch 版本。
- 正式 APK 继续使用现有 release 签名。
- 发布说明注明后台挂机现已包含普通道路道具收益，仍会增加耗电。
- 不更改导出存档格式版本；新增字段采用向后兼容的默认值。
