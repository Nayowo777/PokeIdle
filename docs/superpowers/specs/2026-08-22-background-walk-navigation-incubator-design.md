# Android 后台行走、导航与孵蛋路程结算设计

## 1. 目标

Android 用户开启后台挂机并切到后台或锁屏后，普通道路步行应继续产生与前台一致的行走路程：

- 累加总行走距离；
- 有导航目标时推进 GPS 路线和剩余距离；
- 没有导航目标时仍累加孵蛋所需的总行走距离；
- 孵蛋器达到要求路程后标记为可孵化；
- 后台心跳、恢复前台和重复回调不会重复计算路程。

本次修复只补齐后台期间缺失的数据结算，不在后台播放道路、地图或孵蛋动画。

## 2. 现状与根因

前台每秒 Tick 从 `road.takeDistance()` 读取道路滚动产生的真实像素，并依次执行：

1. 增加 `gameData.stats.walkDistance`；
2. 调用 `gpsAddDistance()` 推进当前导航；
3. 根据 `walkDistance - hatchStart` 检查孵蛋器是否达到孵化路程。

Android 后台模式不会持续执行这个前台 Tick。当前后台时间片只结算：

- 道路道具；
- 自动遇敌与捕获；
- 精灵球和糖果消耗；
- 后台统计及存档事务。

因此 `walkDistance`、GPS 路段和孵蛋状态在后台期间完全不变。根因是后台时间片缺少独立于 DOM 和道路动画的行走结算，而不是 GPS 或孵蛋器界面刷新失败。

## 3. 结算边界

### 3.1 允许累计路程的状态

进入后台时保存本次会话的“普通道路行走快照”。只有同时满足以下条件，后台时间片才累计路程：

- 当前阶段为 `idle`；
- 未骑自行车；
- 未钓鱼，也没有等待中的钓鱼流程；
- 未处于大量出没或时空扭曲事件区域；
- 道路未处于场景切换过渡；
- 道路当前有效移动速度为有限正数。

该快照与现有 `roadItemsEnabled` 采用相同的普通道路判定，但行走速度单独记录，避免后台恢复时依赖已经暂停的道路动画状态。

### 3.2 无导航时的行为

前台即使没有 GPS 目的地，道路仍持续滚动并增加 `walkDistance`，孵蛋器也会获得路程。因此后台必须保持同样规则：

- 无导航目标：增加总行走距离并检查孵蛋器，不改变 GPS 位置；
- 有导航目标或事件点目标：增加总行走距离，同时推进 GPS 路线；
- 开启漫游且已有自动规划路线：按当前路线推进，到达节点后继续现有漫游路线。

### 3.3 不计路程的状态

以下状态进入后台时不增加行走、导航或孵蛋路程：

- 遭遇、捕获动画、战斗、孵化动画等非空闲阶段；
- 自行车状态；
- 钓鱼或等待钓鱼；
- 大量出没、时空扭曲事件区域；
- 道路场景切换过渡。

本次后台会话沿用进入后台时的快照，不在后台模拟道路类型切换、钓鱼触发或自行车状态变化。

## 4. 数据模型

在 `gameData.background` 增加以下向后兼容字段：

- `walkingEnabled`：本次后台会话是否允许累计普通步行路程；
- `walkPxPerSecond`：进入后台时的道路实际移动速度，单位为像素/秒；
- `stats.walkDistance`：后台累计增加的行走像素，用于状态统计和调试。

旧存档缺失字段时分别按 `false`、`0` 和 `0` 处理。非法、负数或非有限速度按 `0` 处理，不产生路程。

GPS 路线和孵蛋器继续使用现有存档结构，不增加第二套进度：

- GPS：`gameData.gps.path`、`seg`、`totalPx`、`remainPx` 等；
- 总路程：`gameData.stats.walkDistance`；
- 孵蛋器：`hatchStart`、`hatchDuration`、`hatched`。

## 5. 纯数据结算模块

新增一个不依赖 DOM、音频和道路 Canvas 的后台行走模块。它接收：

- 当前后台结算状态；
- 时间段 `from` 和 `to`；
- 是否允许步行；
- 每秒移动像素；
- GPS 路线推进适配器；
- 孵蛋距离倍率函数或已解析倍率。

每个有效时间段按以下公式计算：

```text
经过秒数 = (to - from) / 1000
新增路程 = 经过秒数 × walkPxPerSecond
```

新增路程必须是有限且不小于 0 的数值。允许保留小数像素，避免 15 秒后台心跳多次取整产生累计误差。

结算顺序为：

1. 增加 `stats.walkDistance`；
2. 增加 `background.stats.walkDistance`；
3. 若存在有效导航路线，使用同一新增路程推进 GPS；
4. 检查所有未孵化孵蛋器，达到要求后设置 `hatched = true`。

模块不调用 `render()`、`updateGpsViewport()`、`updateIncubatorBadge()`、`saveGame()` 或任何动画函数。恢复前台后由现有入口统一刷新界面。

## 6. GPS 路线推进

### 6.1 复用规则而非复用 UI

现有 `gpsAddDistance()` 同时负责数据推进和界面增量刷新，不适合直接在纯后台模块调用。应把 GPS 距离推进拆成：

- 纯数据函数：消费指定像素，更新路段、节点、目的地和漫游路线；
- 前台包装函数：调用纯数据函数后刷新地图视图；
- 后台调用：只调用纯数据函数，不访问 DOM。

前台和后台必须使用同一个纯数据推进函数，防止两套导航规则逐渐不一致。

### 6.2 跨越多段路线

前台每次路程较短，现有实现到达一段终点后只推进一次。后台一次可能累计数分钟甚至数小时，因此纯数据函数必须循环消费剩余像素：

```text
while 剩余新增路程 > 0 且存在有效导航段：
  本段可消费 = min(剩余新增路程, 当前段 remainPx)
  扣减本段 remainPx
  扣减剩余新增路程
  若本段到达终点：执行现有 advanceSegment 规则
```

必须设置合理的循环保护上限，防止损坏存档中的零长度路线或漫游循环造成死循环。遇到非法路线时停止 GPS 推进，但已经产生的总行走距离和孵蛋路程仍然保留。

### 6.3 到达目的地

- 普通目的地：到达后清除导航，后续剩余后台路程只计入总路程和孵蛋，不继续移动 GPS。
- 漫游：到达节点后按现有漫游路线规划下一站，并继续消费本时间段剩余路程。
- 事件点：沿用现有事件点到达规则，停在事件点，不用剩余路程穿过事件区域。
- 自行车目标：本次功能不模拟后台骑行；进入后台时若为骑行状态，整个会话不计路程。

## 7. 孵蛋器结算

将现有前台孵蛋达标判断提取为可复用纯函数。对每个未孵化槽位：

```text
已使用路程 = stats.walkDistance - hatchStart
所需路程 = hatchDuration × 当前 hatchDist 随从倍率
```

满足以下任一条件时设置 `hatched = true`：

- `hatchStart` 或已使用路程无效；
- 已使用路程小于 0；
- `已使用路程 + 100 >= 所需路程`，保留现有 100 像素容差。

随从增益只按时间段内有效状态计算。若随从的 `hatchDist` 增益在后台期间到期，结算应在到期点分段：到期前使用增益倍率，到期后使用普通倍率，并在每段增加路程后检查是否达到孵化要求。

后台只标记“可孵化”，不直接播放孵化动画、不生成宝可梦、不增加孵化统计。玩家返回孵蛋器后继续沿用现有领取和孵化流程。

## 8. 与后台遇敌和道具的时序

后台行走与道路道具共用 `settleBackgroundSlice()` 的 `resolveElapsed` 时间段回调：

```text
开始时间
  -> 结算到第 1 次遇敌前的行走、导航、孵蛋和道路道具
  -> 结算第 1 次遇敌
  -> 重复处理后续时间段和遇敌
  -> 结算最后一次遇敌到 now 的行走、导航、孵蛋和道路道具
  -> 严格保存一次
```

若捕获过滤器产生暂停遭遇，所有路程只结算到暂停点；暂停之后的时间留待处理遭遇后继续结算。这样行走、导航、孵蛋、道具和遇敌共享同一个时间游标，保证幂等性。

## 9. 事务、幂等性与恢复

- 继续通过 `_backgroundSettlementQueue` 串行处理后台心跳和恢复事件。
- 相同或更早的 `now` 不增加路程。
- 单次最多结算最近 24 小时，与现有后台遇敌规则一致。
- 所有数据先在存档副本中修改，严格保存成功后才替换内存状态。
- 保存失败时恢复原存档，下一次心跳可完整重试。
- 存在 `pendingEncounter` 时不推进时间和路程。
- 前台恢复后刷新统计、GPS、孵蛋器红点和手机聚合红点，不重复结算。

## 10. 测试策略

### 10.1 后台行走纯函数

- 60 秒、30 像素/秒产生 1800 像素路程。
- 连续多个心跳保留小数像素且总量准确。
- `walkingEnabled = false`、非法速度或非法时间段不增加路程。
- 相同时间戳和时间回拨不重复增加。
- 后台统计与总行走距离同步增加。

### 10.2 GPS 推进

- 单段内扣减 `remainPx`。
- 一次大路程跨越多个路线段。
- 到达普通目的地后停止导航，剩余路程不改变 GPS。
- 漫游到达节点后自动规划下一站并继续推进。
- 到达事件点后停止，不穿过事件点。
- 损坏或零长度路线不会死循环。
- 前台 `gpsAddDistance()` 继续调用同一个数据推进核心。

### 10.3 孵蛋器

- 后台新增路程达到阈值后标记 `hatched`。
- 无导航时仍可累计路程并孵蛋。
- 多个孵蛋器按各自 `hatchStart` 和 `hatchDuration` 独立判断。
- 保留 100 像素容差和非法起始值兜底。
- `hatchDist` 随从增益到期前后分段生效。
- 后台不直接增加 `totalEggsHatched` 或创建仓库宝可梦。

### 10.4 集成与回归

- 同一时间片按“行走与道具 -> 遇敌”顺序执行。
- 暂停遭遇后不结算暂停点之后的路程。
- 严格保存失败时路程、GPS 和孵蛋状态全部回滚。
- 旧存档缺失新增后台字段时安全加载。
- 完整测试和移动端测试全部通过。
- `npm run android:prepare` 成功。

## 11. 真机验收

1. 在普通道路设置一个距离较远的导航目的地，并给孵蛋器放入未孵化的蛋。
2. 记录当前总行走距离、GPS 剩余距离和孵蛋剩余距离。
3. 开启后台挂机并锁屏 5 分钟以上。
4. 返回前台，确认总行走距离增加、GPS 剩余距离减少、孵蛋剩余距离同步减少。
5. 锁屏到足以到达导航目的地，确认位置正确抵达；漫游开启时确认会继续下一段。
6. 锁屏到足以完成孵蛋，确认孵蛋器出现可孵化红点，但不会在后台自动播放孵化动画。
7. 分别在无导航、骑行、钓鱼、战斗和特殊事件区域重复测试：无导航应继续孵蛋，其余状态不增加路程。

## 12. 发布边界

- Android 版本递增 1 个 patch 版本。
- 不修改存档导出格式版本；新增字段使用默认值兼容旧存档。
- 正式 APK 继续使用现有 release 签名。
- 设置页后台挂机说明更新为包含普通道路行走、导航、孵蛋、道具和自动捕获。
